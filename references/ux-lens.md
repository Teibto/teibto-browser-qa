# UX/UI lens — จับบั๊กที่ functional test มองไม่เห็น (token-safe)

functional test ตอบได้แค่ "หน้าขึ้นไหม ปุ่มกดติดไหม" · บั๊กที่ผู้ใช้ด่าจริงอยู่คนละชั้น —
หน้าล้นแนวนอนบนมือถือ, ปุ่มเล็กกว่านิ้ว, ข้อความหายไปเฉย ๆ, dark mode อ่านไม่ออก,
กด Tab แล้ววนไม่ครบ, API ตอบ 500 แล้วหน้าจอว่างโดยไม่มี error

`cdp.py` ตอบได้หมดผ่านคำสั่ง `lens` ซึ่งคืน **คำวินิจฉัย ไม่ใช่ข้อมูลดิบ**

```bash
AB lens layout
# {"lens":"layout","verdict":"FAIL","count":2,"findings":[
#   {"kind":"overflow-x","sel":"document","detail":"1180px > viewport 390px"},
#   {"kind":"tap-target-small","sel":"nav > a.menu","detail":"18x18 < 24x24 (WCAG 2.2 AA)"}]}
```

---

## 1. เลือก lens ให้ตรงคำถาม

| lens | ตอบคำถาม | ต้องอยู่ใน `run` |
|---|---|---|
| `layout` | ล้นแนวนอน · tap target < 24x24 · ข้อความถูกตัดหาย | ไม่ |
| `responsive <w1,w2,..>` | พังที่ความกว้างไหน (วน `layout` ทุกความกว้าง) | ไม่ |
| `theme` | ตัวหนังสือสีเดียวกับพื้นใน dark/light · หน้ารองรับ dark mode ไหม | ไม่ |
| `focus [n]` | ลำดับ Tab · focus trap · ไม่มีเส้นบอกโฟกัส · เดินไม่ครบ | ไม่ |
| `netlog` | HTTP >= 400 · request ที่ล้ม · CSP/mixed content | **ใช่** |

คู่กันคืออีกสองคำสั่งที่ไม่ใช่ lens:

- **`steady`** — หยุด animation/transition/smooth scroll ก่อนวัด · ไม่ทำแล้ว visual/layout จะ flaky
  จนคนเลิกเชื่อผล · `--tz`/`--locale` ตั้งได้เฉพาะในโหมด `run`
- **`stub <urlที่ตรง> <status>`** — ปลอมคำตอบเพื่อบังคับหน้าจอเข้าสถานะ **empty / error**
  ซึ่งทดสอบไม่ได้เลยถ้าข้อมูลจริงไม่ว่างและ API ไม่พัง · เป็น **actuator ไม่ใช่ lens**
  (มันเปลี่ยนสิ่งที่เกิดขึ้น ไม่ได้อ่านอย่างเดียว)

## 2. ท่ามาตรฐาน — หนึ่ง `run` ได้หลาย lens

`Emulation`/`Fetch`/`Network` ตายพร้อม websocket ของแต่ละคำสั่ง → งานที่ต้องข้ามคำสั่งต้องอยู่ใน `run`

```bash
cat > qa/orders/lens.txt <<'EOF'
netlog on
steady --tz=Asia/Bangkok --locale=th-TH
stub /api/orders 200 --bodyfile=D:\qa\empty.json
nav https://app.example.com/orders 3
lens layout
lens theme
lens focus 30
lens netlog
EOF
AB run qa/orders/lens.txt
```

รอบเดียวได้ครบ: หน้าจอสถานะ empty + ผลตรวจ 4 ชั้น + error ฝั่ง network — และเป็น **round-trip เดียว**
แทนที่จะเป็นสิบครั้ง

## 3. อ่าน verdict — และกฎข้อเดียวที่ห้ามหย่อน

`verdict` มีสามค่าเสมอ:

| verdict | แปลว่า | ทำอะไรต่อ |
|---|---|---|
| `PASS` | ตรวจแล้ว ไม่เจอ | ผ่านชั้นนี้ |
| `FAIL` | ตรวจแล้ว เจอ | อ่าน `findings` |
| **`UNVERIFIED`** | **ตรวจไม่ได้** | **ห้ามนับเป็นผ่าน — แก้ให้ตรวจได้ก่อน แล้วตรวจใหม่** |

> **"ไม่มี finding" กับ "ไม่ได้เฝ้าอยู่" คนละเรื่อง และอันหลังอันตรายกว่า**
> `lens netlog` ที่ไม่ได้สั่ง `netlog on` มาก่อน จะคืน `UNVERIFIED` ไม่ใช่ `PASS` — เพราะถ้าคืน PASS
> รายงานจะเขียนว่า "ไม่มี error ฝั่ง network" ทั้งที่ไม่เคยดูเลย · เหตุผลเดียวกับ `console`
> ที่ error แทนที่จะคืน `[]` เมื่อไม่มี collector (`gotchas.md` §2)

เขียนลง `qa-report.md` ให้แยกสามค่านี้ออกจากกันเสมอ — รายงานที่รวม `UNVERIFIED` เข้ากับ `PASS`
คือรายงานที่โกหกโดยไม่มีใครตั้งใจ

## 4. lens แต่ละตัว "โกหก" ได้ยังไง

ก่อนเชื่อผล ต้องรู้ว่ามันพลาดตรงไหนได้บ้าง:

### `layout`

- **นับเฉพาะสิ่งที่มองเห็นอยู่ตอนนั้น** — เมนูที่ยังไม่กาง, tab ที่ยังไม่เปิด, modal ที่ยังไม่ขึ้น
  ไม่ถูกตรวจเลย · ต้อง `click` ให้ state นั้นโผล่ก่อนแล้วค่อยยิง lens ซ้ำ
- **`tap-target-small` ดูขนาดกล่องของ element เอง** ไม่ได้ดูพื้นที่กดจริงที่พ่อของมันอาจขยายให้
  (padding ของ `<li>` ที่ครอบ `<a>`) → เจอ false positive ได้ในเมนูบางแบบ
- **ล้นแนวนอนรายงานเฉพาะตัวที่ "ยื่นออกไป"** ตัวที่กว้างเกินจอทั้งก้อนจะถูกรายงานที่พ่อของมันแทน
  เพื่อไม่ให้ได้ finding เป็นร้อยที่ชี้ไปที่เดียวกันหมด

### `responsive`

- **หน้าที่ไม่มี `<meta name="viewport">` ได้ layout 980px เสมอ** ใต้ mobile emulation — สั่ง 390
  แล้ววัดได้ 980 **ไม่ใช่บั๊กของเครื่องมือ** มือถือจริงก็เห็นแบบนี้ · lens รายงานเป็น
  `no-viewport-meta` ให้แล้ว อย่าไปไล่แก้เครื่องมือ
- **ห้ามใช้ `innerWidth` ตัดสินว่า override ติดหรือยัง** — ขนาดหน้าต่างค้างข้าม invocation อยู่แล้ว
  เทสจะ "ผ่าน" ทั้งที่ override ไม่ได้อยู่จริง · ใช้ `devicePixelRatio` แทน

### `theme`

- **เทียบสีแบบตรงตัว** (`color` เท่ากับพื้นหลังที่มีผลจริง) → จับ "ตัวหนังสือหายสนิท" ได้ แต่
  **จับ contrast ต่ำไม่ได้** (เทาอ่อนบนขาว) · งาน contrast เป็นของ `a11y-layer.md` (axe-core)
- พื้นหลังที่เป็นรูปหรือ gradient ทำให้ `__bg` หาสีไม่เจอ → อาจพลาด

### `focus`

- **ต้องกด Tab จริงเท่านั้น** — `el.focus()` ไม่ทำให้ `:focus-visible` ทำงาน แล้วจะได้
  `no-focus-ring` ยกแผงแบบผิด ๆ (`gotchas.md` §16)
- เดินตาม Tab เท่านั้น ยังไม่ตรวจ arrow-key navigation ของ component (grid/menu ของ JET)
- `no-focus-ring` ดูแค่ `outline`/`box-shadow` — ธีมที่บอกโฟกัสด้วยการเปลี่ยนสีพื้นล้วน ๆ
  จะถูกฟ้องทั้งที่คนเห็นได้

### `netlog`

- เก็บได้เฉพาะช่วงที่ `run` ยังอยู่ — request ที่เกิด**ก่อน** `netlog on` ไม่ถูกเก็บ
- `Log` domain มี warning ที่ไม่ใช่บั๊กปนมาได้ (deprecation) → อ่าน `kind` ก่อนตัดสิน

## 5. สิ่งที่ lens **จงใจไม่ฟ้อง**

ด่านที่ฟ้องทุกอย่างไร้ค่าพอ ๆ กับด่านที่ไม่เคยฟ้องอะไร — สามข้อนี้ตัดออกโดยตั้งใจ:

1. **ข้อความที่ตัดด้วย `text-overflow: ellipsis`** — เป็นการตัดที่ตั้งใจและมีสัญญาณบอกผู้ใช้
2. **หน้าที่ไม่รองรับ dark mode** — หลายหน้าไม่รองรับโดยตั้งใจ · รายงานเป็น
   `dark_mode: not-supported` ให้คนตัดสิน ไม่นับเป็น finding
3. **โฟกัสออกนอกหน้าหลังเดินครบทุก element** — เป็นพฤติกรรมปกติของเบราว์เซอร์
   (ฟ้องเฉพาะตอนหลุดออกไปทั้งที่ยังเหลือ element ที่โฟกัสได้)

ถ้าเจอเคสที่ lens ฟ้องมั่วซ้ำ ๆ ให้แก้ที่ `cdp.py` แล้วเพิ่มเทสคู่ใน `tests/test-cdp.sh`
ของ `teibto-dev-standards` — **ห้ามแก้ด้วยการสอนคนให้ "ข้าม finding ประเภทนี้"**
เพราะความรู้แบบนั้นอยู่ได้แค่ในหัวคนที่อ่านผ่าน

## 6. ต่อกับของเดิม

- **`a11y-layer.md`** — axe-core ครอบ contrast/ARIA/label · lens ครอบสิ่งที่ axe ไม่ดู
  (ล้นแนวนอน, tap target, ลำดับ Tab จริง, network) · ใช้คู่กัน ไม่ใช่แทนกัน
- **`visual-regression.md`** — รัน `steady` ก่อนถ่าย baseline และก่อนถ่ายภาพเทียบเสมอ
  ไม่งั้น diff จะ noise จาก animation ที่ค้างคนละเฟรม
- **`coverage-model.md`** — lens ที่คืน `UNVERIFIED` ต้องนับเป็น **ยังไม่ได้ตรวจ** ในตาราง coverage
  ไม่ใช่ตรวจแล้วผ่าน
- **คำสั่งครบชุด** → `commands.md` · **กับดักของ Chrome/หน้าเว็บ** → `gotchas.md`
